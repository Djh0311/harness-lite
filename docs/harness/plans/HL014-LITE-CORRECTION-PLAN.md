## 1. 版本定位

**0.14 不增加一套管理体系，而是让已有能力真正可用、少误停、少误报，让用户少接管。**

你的核心不是“把 Harness 的流程走完”，而是：

> 模型记住用户目标，依据事实持续推进，走错会纠偏，协作有人接住，交付可以相信；用户不需要维护 Harness。

因此，本版不以修完观察报告的十二条建议为目标。每项改动必须回答三个问题：解决了哪个真实反例，用户因此少承担什么，是否能复用已有机制。

### 不可破坏的六项能力

| 核心能力 | 0.14 的要求 |
| --- | --- |
| 意图不丢失 | 当前用户目标、边界和完整成功条件优先；leaf、receipt、Hook 只是投影，不能扩权 |
| 工作能持续 | 已授权、可恢复的普通工作直接推进；用户不当“继续按钮”，旧状态不拖停无关工作 |
| 错误会纠偏 | 用最短直接证据更新路线；保留一个 `focus / decisionQuestion / nextAction`，不加规则书 |
| 协作有人接住 | 真实工具决定委派；reported 先验收，accepted 才解锁真实依赖，独立分支继续 |
| 完成值得相信 | 没执行检查不算通过，测试绿不等于产品完成，缺结果保持未完成 |
| 管理负担足够低 | 用户日常 Harness 命令仍为 0，不新增登记、审批、身份维护和后台服务 |

`decisionQuestion` 是模型要解决的判断，不是要求模型每轮向用户提问。

## 3. 本版产品范围

### 3.1 接通已有能力，不增加用户入口

**用户得到的变化：说清目标和边界后，不再需要手写租约或手工移动 leaf。**

问题：`authorization.issue()` 和 `tree.exit/pause/resume()` 已有实现，但缺少生产调用链。不能只补说明文字，继续让模型拼精确 JSON 或用 `mv` 代替产品入口。

候选实现路径：

```text
真实 UserPromptSubmit 来源收据
→ 模型按完整请求维护最小工作投影
→ 现有 Hook 消费本轮执行或生命周期意图
→ 调用已有 issue / exit / pause / resume
→ 继续普通工作，或按真实条件收口
```

- 模型负责理解自然语言和决定下一步；Harness 不用“看看”“修复”“继续”等关键词判授权。
- 复用现有 turn 状态承载一个待消费意图及其当前来源收据引用，不增加状态文件或第二套账本。绑定、到期时间和安全移动由代码处理，模型不手写这些细节。
- 主管通过宿主 Bash 工具调用固定 `--work-intent` 内部入口，`PreToolUse` 校验执行投影、来源收据和本轮 leaf/stage 后调用 `issue()`；helper 只读回登记结果。`Stop` 只校验有效执行绑定和新语义进展，不签发或续期。不是每次收到消息都自动发放。
- 仅规划、仅评审、用户叫停或撤回的请求不能取得执行资格。内部续跑消息、子代理消息、旧 turn 投影也不能发放或续命。
- 保留当前 project/session/turn/leaf/stage 绑定和现有短期上限；不做跨轮租约。同一轮内的续跑不扩范围，也不产生新的用户授权。
- 生命周期意图由现有 Hook 在相关事件消费，调用既有安全移动函数。完成退场必须对应真实验收结果和证据，不能看到 `CLOSED` 或 `complete` 字样就归档。
- 多个 current 时不擅自选一个或移动用户文件。只停用依赖唯一 leaf 的自动能力；模型可以查证并修复明确的投影问题，其他已授权的安全工作不被冻结。
- 六个内部 CLI 顶级接口保持 `status / verify / map / mistake / install / selfcheck`。不新增 `authorize` 命令，不把生命周期伪装成 `map` 的无关职责。

这是一处已有能力的接线，不是新的授权产品。验收必须从真实来源事件走完整路径，直接调用 helper 的测试不够。

### 3.2 旧状态不能阻止无关工作

**用户得到的变化：昨天没确认的 push，不会让今天的本地开发停下来。**

- 修复 D25：待确认状态只影响它对应的 push 动作，不再因项目内存在任意 pending 就压住普通续跑。
- 旧 session、旧目标或缺少有效绑定的记录不作为当前普通工作的停点，也绝不作为 push 授权。
- 当前确实只能等待该目标的用户决定时，让出并说明原因；有其他独立、已授权工作时继续，不反复生成确认问题或空转续跑。
- 保留精确 push gate：HEAD、目标、push URL、来源收据和一次性消费继续校验。状态失效不等于允许 push；再次执行必须走有效绑定。
- 不增加 TTL 清理服务，不删除旧记录来掩盖问题，不以“超时自动同意”恢复。
- 保留新语义进展和重复 token 抑制。无新进展、目标已经完成或用户已叫停时，不强制续跑。

同时补 D20 的已有边界消费：合并 stage 与 leaf 的明确禁动路径，供现有续跑判断、越界报告和相关范围检查使用。缺少 `allowed` 元数据、没有 current leaf 或必要相邻路径，不自动等于禁止。

这不新增通用文件权限引擎，也不声称当前 Hook 能在所有宿主工具写入前拦住禁区。明确禁区必须被模型遵守；已发生的禁区变化不能漏报或继续取得自动续跑资格，其他无关工作仍保持局部处理。

### 3.3 结果和停点说真话

**用户得到的变化：不会被“没有检查但通过了”误导；需要排查时能知道为什么没继续。**

**空 verify：**

- 实际执行检查数量为 0 时，返回“未执行检查”，不生成成功结论，不显示“通过”。
- 可以保留一条真实的未执行记录；明确本轮未验证。历史成功仍是历史，不能跳过空回执后沿用旧成功给本轮背书。
- 真实检查成功、失败和人工检查继续分开。空记录、文件变化或 HEAD 变化都不单独算语义进展。
- 向后读取旧 `no checks` 回执时，不把其 `ok:true` 展示为有效通过；不改写历史文件。

**最小停点说明：**

- 复用 `.observed.jsonl` 和现有 status，不建审计库、不保存完整判断向量。
- 每次相关事件只记一次最终结果，保留 session/turn、结果、一个主要原因和必要对象引用，例如“未取得本轮执行绑定”“无新语义进展”“该 push 等待决定”。
- 权限拒绝不能只写 `executed`。不续跑的 Stop 也要在删除临时 turn 前留下最小结论。
- status 读取匹配上下文的最近结果；旧记录只有 `executed` 时，原因记 `UNKNOWN`，不补猜。
- 正常工作不逐轮输出这些诊断，不复述整套规则。硬风险真命中时仍说明动作、目标、边界、风险和用户需要决定什么。
- 不记录原始用户消息、凭据或完整工具输入。收据里的对象信息也要按现有脱敏规则处理。

### 3.4 产品身份和运行环境分开

**用户得到的变化：换一个可用 Node，不再被误报成 Harness 产品遭到修改。**

- 产品身份继续校验运行文件、受管路径、指令块、Hook 语义和既有独立锚点；仅把合法 Node 启动器的绝对路径从产品语义摘要中分离。
- Node 路径、版本、可用性作为运行诊断单独保留。实际 Hook 是否可启动、宿主是否执行，是另一项事实，不从摘要一致推导出来。
- 只规范化受支持的直接 Node 启动形式。额外 shell 动作、wrapper、危险参数、dispatcher 目标和 Hook 事件变化不能被一起忽略。
- 安装器、dispatcher/bootstrap、managed 路径和观测摘要使用一致定义，不只改某一个检查点。
- 旧身份按旧规则解释，新身份通过显式升级生成。禁止直接把期望 digest 改成当前内容来“自愈”，也不关闭校验换取绿测。
- status 区分文件存在、身份校验、宿主事件观察。没有新鲜事件就标“未观察/UNKNOWN”；不能简单写“未安装”，更不能猜测宿主一定不信任。
- 异常只影响对应的受管写入、身份声明或自动能力。不能阻止模型继续普通安全工作；原有硬风险保护不得因此放松。

不建立新的信任中心、签名服务或环境管理器。

### 3.5 可逆性不退步，Cursor WIP 不默认接受

**用户得到的变化：升级或撤回 Harness，不会顺带删掉用户 Hook 或已有配置。**

本版涉及安装身份，必须保留已有 ownership、preimage、回滚和零写 HOLD 契约。

当前 Cursor WIP 已发现两个反例：

1. 含 Harness 路径和 `--host cursor` 的自定义复合命令可能被误认成旧受管命令，进而删除。
2. 安装前已有的空 `.cursor/hooks.json` 或空事件声明可能在卸载时丢失。

若 0.14 的候选包含该 WIP，必须先修复这两个反例并验证精确恢复；不能仅因适配测试绿就发布。如果不包含，按明确的候选文件边界排除，不改动或丢弃用户当前 WIP。

本方案原本不新增宿主；2026-10-22 按用户要求加入 Claude Code，并已在真实宿主上验证。Cursor 的产品支持只能按实际通过的适配、安装撤回及真实宿主证据分别声明，不从本地编码测试推导实时健康；它现在默认不装。

### 3.6 测试按需维护（2026-10-22 补充，证据触发）

**用户得到的变化：过时测试会随产品迭代被更新、合并或删除；不会有人靠删测试把结果变绿，也不会每轮都去翻测试库。**

用户确认的节奏：

- **按需为主**：只在影响当前开发时当场处理，包括改动改变了某个测试保护的行为、相关测试失败、功能被删除或替换。
- **阶段收尾查漏**：集中处理重复测试、废弃功能留下的测试，以及开发中记下的待定项；只看本阶段相关的部分。
- **全库清理**只在大重构后或用户要求时做；没有相关问题就跳过。

| 情况 | 处理 |
| --- | --- |
| 当前要求没变，测试仍有独立的保护作用 | 保留 |
| 功能还在，行为变了 | 更新 |
| 多个测试保护同一行为 | 合并，保留边界情况 |
| 功能已删除，没有兼容承诺，也不顺带保护别的 | 删除 |
| 拿不准 | 先保留并记一笔，不影响其他工作 |

测试失败不能直接当作测试过时；要求没变，就修产品。删改的理由写一句进交付说明，不逐项找用户确认。

运行时原计划只落 §0 那一个短语。实测证明短语无效，已撤回；现在按 §0 的追加要求，只在阶段最后一个 leaf 退场时给出一条 `nextAction`（W4v5b，已在真实宿主验证并保留）。上表是设计依据，不进运行时上下文。问题真实存在的证据：用户 2026-09-13 对 Syn 的修正里写过“不得以过时红测重开任务”。那是 0.8 指令下的情况，现行指令下是否仍会发生，由工作计划 W2 实测。

## 4. 明确不做什么

| 观察报告建议 | 0.14 的取舍 |
| --- | --- |
| 授权入口、跨轮租约 | 接通已有发放路径；跨轮重新授权设计不做 |
| 生命周期与自愈 | 接通既有移动；不自动清理多个 current 或仅凭自报归档 |
| Stop 判断向量、权限审计 | 只留一个最终结果和主要原因，不建全量决策日志 |
| 身份、出处、status | 分离启动器，沿用升级与锚点，诚实展示；不重建信任体系 |
| 空 verify | 补齐未执行语义和历史读取 |
| pending push TTL | 用动作相关性消除误停，不用超时放行或后台清理 |
| writer/reviewer 身份系统 | 不做角色注册库；本版验收仍要求未参与实现者复核实际证据，同人接管必须披露 |
| leaf 禁区 | 修已有边界消费，不扩成普通写文件逐次审批 |
| 异常终止记账 | 未见 Stop 就保持未结束/未知，不伪造 Stop；不加监控器和全中断恢复状态机 |
| WIP 统计、usage 卫生 | 本轮证据与产品结果分开；不批量清理旧账，不自动改用户 gitignore，不统一所有旧统计 |
| 证据耐久、中断恢复 | 本版验收证据存持久目录；provider 重连、relay、宿主重启恢复不属于 Lite |
| bench 回归 | 纳入正式行为测试，复用已有 runner，不另造测试平台 |

也不做静态模型目录、provider 连接、daemon、agent 调度器、并发管理平台、第二套 prompt 数据库。2026-10-22 重审后，以下几项同样不做：接通 skills、清理 Harness 自身的历史测试、为测试维护新增事件、命令、必填字段、清单或每轮检查。W4v5 的 `nextAction` 是阶段收尾时返回结果里的一条提示，不要求模型填写，也不拦截任何动作；这是按用户追加要求、有实测依据的例外。

0.13 的 Astra 主管设计继续保留：writer 按当前真实工具选择；普通层五次不同有效语义失败后进入 Astra 有界恢复，默认三次、问题级 1..5；工具、队列、传输、认证、中间红和沉默不计。恢复耗尽仍只影响当前问题，不恢复旧 Terra/Sol 必需链。

## 5. 验收：证明更省心，而不是日志更多

### 5.1 确定性正反例

| 场景 | 必须观察到的行为 |
| --- | --- |
| 自然语言要求完成一个范围明确的任务 | 实际来源事件→模型投影→既有发放函数→有效 Stop 路径；无需手写租约或用户 Harness 命令 |
| 只规划、只评审、撤回、内部消息、子代理消息、旧投影 | 不获得执行资格，不开始或续跑产品实现 |
| 有新语义进展 / 无进展 / 已完成 / 重复 token | 分别按真实状态继续或收口；不空转，不多跑一轮来凑记录 |
| pause/resume/完成退场 | 经正常生产入口调用安全移动；目标冲突、缺验收或来源不匹配时不覆盖、不伪归档 |
| 旧 pending 与当前普通工作无关 | 普通工作能继续；真正 push 仍必须获得本次精确授权 |
| stage 或 leaf 禁区发生变化 / 普通相邻路径变化 | 前者被识别且不取得相关自动续跑；后者不被当作普遍禁止 |
| 空 verify / 实际通过 / 实际失败 / 人工检查 / 旧空成功回执 | 五类结果不混淆；无检查不显示通过、不生成进展 |
| 权限准拒与 Stop 不续跑 | 各留一次最终结论；主要原因可读回，临时 turn 删除不丢结论 |
| 支持的不同 Node 路径 / runtime、指令或 Hook 实质变化 | 前者不误报产品漂移；后者仍被识别；实际启动失败另报 |
| 安装、显式 0.13 升级、故障回滚、卸载 | 恢复用户原文和配置；ownership 歧义零写，不强迫清 WIP |
| 候选包含 Cursor WIP | 自定义复合 Hook、既有空配置及空声明均被保留或精确恢复 |
| 局部 UNKNOWN、无 current、一个 unit 未验收或恢复耗尽 | 不伪造完成，不解锁真实依赖；独立的已授权工作不受牵连 |

复用现有相关测试，重点覆盖 `current-contracts`、`nv03-hook-work`、Astra 行为、安装 ownership 和纳入候选的宿主适配。聚焦测试后运行 `npm test` 当前门槛；历史套件仍单列，不能把历史契约差异混算成 0.14 回归。

源码通过后，用现有 candidate builder 物化同一候选，核对源码与物化运行行为。升级与回滚在隔离项目验证，不在 Syn 实际安装上试错。

### 5.2 真实模型行为（2026-10-22 重审后）

用户已确认的二十条黑箱行为标准和六项核心能力仍是判分依据，不能用字段齐全或关键词出现来代替。

不再做 0.13 与 0.14 三类代表任务的大对照，只验证真正还不知道的事：

1. **真实宿主一次**（工作计划 W1）：在隔离项目里用 Codex，从自然请求开始，观察这几件事：
   - 只规划时不开工；
   - 模型会不会自己登记开工、自己退场；
   - 兜底续跑能否触发；
   - 旧 push 会不会卡住人；
   - Harness 让模型多做了多少步；
   - 用户结果是否真的做完。
2. **测试维护四个场景**（W2，必要时由 W4 复跑）：需求变了、产品改坏了、阶段收尾、无关小任务。先用现行指令跑出基线；确认确实有缺口，才加常驻短语；加了之后，再证明缺口已补上、且没有带来副作用。

判分标准在运行前写定，不事后挑成功样本。新规则如果没有可重复的用户收益，就删除或延期，不为了十二条建议齐全而保留。

固定 JSON 决策测试只是补充，不能证明实际委派、持续执行或宿主 Hook 可达。

### 5.3 真实路径和结论分层

声称“用户不再当继续按钮”前，必须在拟声明支持的真实宿主上，从用户自然请求开始，看到正常 Hook 路径和多个工作单元的连续推进。观察者手写租约、移动 leaf、代开下一轮或改被测 runtime 的记录不能用于此结论。

证据保存在持久的验收目录，不只放 `/tmp`。复用现有报告，分别给出：

- 产品反例修复和当前回归；
- 真实模型行为与用户负担；
- 实际宿主安装、Hook 可达和续跑；
- 升级、回滚及用户内容保护。

未覆盖项写 `NOT-COVERED`，环境不成立写 `BLOCKED-TEST-SETUP`，证据不足写 `UNKNOWN`。某条真实路径没验证不阻止其他独立修复，但不能把缺项换算为 PASS 或宣布对应能力完成。
